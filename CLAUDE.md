# Shared bibliography

This repo holds one bibliography that serves all of the author's repos. Follow these rules when adding, fixing, or citing references from it.

- One bibliography serves all repos. Paperpile holds the library. Paperpile's automatic BibTeX export commits it as BibLaTeX to `references.bib` in the public repo `github.com/jovo/bib`. Repos never keep their own `.bib`.
- Add, fix, or deduplicate references in Paperpile, never by editing `references.bib`. Agents add papers with the Paperpile MCP server (the `paperpile` plugin from the `Paperpile/agent-plugins` marketplace). `save_to_library` takes DOIs or a BibTeX string, skips papers already in the library, and returns each paper's citation key. Load the plugin's `find-papers` skill before searching for a paper.
- Before importing BibLaTeX into Paperpile, reduce double-braced titles `{{...}}` to single braces (Paperpile stores the inner pair as text) and rewrite `family=..., given=...` names as `Family, Given`.
- Repos read the bib with `bin/fetch-bib`. A project copies it to `build/fetch-bib.sh` and runs it from its Makefile (`$(BUILD)/references.bib: FORCE` then `$(BUILD)/fetch-bib.sh $@`), and git-ignores `build/references.bib` and `build/*.etag`. On a machine with this repo cloned at `~/github/bib` (or `$BIB_DIR`), it pulls the clone and links to its `references.bib`. Elsewhere it downloads `https://raw.githubusercontent.com/jovo/bib/main/references.bib` only when the file changed (an ETag check), and keeps the cached copy offline. A new entry reaches GitHub at Paperpile's next export, and GitHub caches the raw file for about 5 minutes after that. A standalone Markdown file can instead set `bibliography: <that URL>` in its YAML front matter, which pandoc 3.9 reads directly. When this script changes, update the project copies from it.
- Citation keys come from Paperpile. Never hand-construct a key. Look it up in `references.bib`, or read it from `save_to_library` or `get_references_from_library`. Paperpile assigns its own key on import, even when a BibTeX entry carries one.
- Key shape is `SurnameYY` (e.g., `Friston10`). Hyphens and the stored case of particles are kept: `Aston-Jones00`, `vanRooij19`. On collision the first entry stays bare and later ones get `b`, `c`, ... (`DeSilva22`, `DeSilva22b`). Entries missing author or year get `OtherOther...` keys. Fix the metadata in Paperpile rather than citing those.
- `references.bib` is BibLaTeX. Paperpile wraps titles in double braces so CSL styles keep their casing.
